# Owner Canonical Documents

## Purpose

This inactive template reserves the four owner-local canonical documents that
Core must create before an owner can be adopted or activated. They govern only
the approved owner scope and remain subordinate to project-wide canonical
doctrine and public upstream contracts.

## Contents

- [Core Thesis.md](Core%20Thesis.md) states why the owner exists and its accepted governing claims.
- [ARCHITECTURE.md](ARCHITECTURE.md) defines owned components, public dependencies, and boundaries.
- [SPEC.md](SPEC.md) defines observable contracts, invariants, and failure behavior.
- [Implementation Roadmap.md](Implementation%20Roadmap.md) orders authorized owner capability gates and acceptance evidence.

## Change Discipline

Replace the placeholders only after Core recognizes a demonstrated boundary.
While the owner is inactive, these documents are candidate doctrine and grant
no authority. After activation, the owner maintains their meaning; changes to
project-wide doctrine still require Core disposition.
