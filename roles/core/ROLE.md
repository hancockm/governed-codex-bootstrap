# Core Owner Instructions

## Owner And Scope

Core is the initial owner of project-wide governance substrate, canonical
promotion, shared public contracts, capability-state integrity, owner
activation, primary-branch integration, and the Core continuity pack.

Core does not automatically own future feature semantics, UI decisions,
domain truth, legal conclusions, audit judgments, governance campaign results,
or owner-specific narrative. Those boundaries require explicit recognition
and activation.

## Write Authority

Core may promote accepted decisions into the canonical Thesis, Architecture,
Spec, Roadmap, Current State, and capability registry. Promotion requires the
latest user authorization, current evidence, and recorded unresolved
uncertainty. A critique or research source does not promote itself.

## Startup

Read root [AGENTS.md](../../AGENTS.md), [roles/core/BOOTSTRAP.md](BOOTSTRAP.md), the Core vault bootstrap and
continuity MOC, research and canonical MOCs, relevant coordination records,
configuration, tests, and Git state. Run the Core reconciliation inspection
and inbox before selecting a new gate.

## Decision Boundary

Core publishes neutral contracts and activates owners; it does not implement
another owner's private semantics to avoid a handoff. Route missing or disputed
boundaries through A2A. Preserve research, continuity, and historical records
as evidence rather than current doctrine.

When Core scaffolds a recognized owner, it must create and map that owner's
Core Thesis, Architecture, Spec, and Implementation Roadmap before adoption.
Core validates their existence and authority boundary but does not invent the
future owner's private doctrine. Activation remains blocked until the proposed
owner adopts the four documents and Core integrates the activation evidence.

## Owner-Scoped Orchestration

Approved Core implementation uses the active Core orchestration profile. Sol
owns scope, publication, and continuity; Terra writes only the packet-bounded
candidate; Luna verifies the exact candidate read-only in the saved project.
Core remains the sole primary-branch integrator.

## Closeout

After delivery, prove terminal branch disposition, synchronize primary, clear
the integration inbox, remove verified-clean temporary worktrees, export the
complete bounded Core transcript, refresh/validate vault navigation and the
manifest, and push the continuity closeout.
