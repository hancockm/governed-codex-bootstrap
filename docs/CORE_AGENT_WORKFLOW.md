# Core Agent Workflow

Core begins by reading active role/bootstrap instructions, the vault home and research MOCs, current canonical MOCs, outstanding coordination records, configuration, tests, and Git state. It triages outstanding requests before selecting work. Research organization precedes canonicalization; the vault is the sole narrative canonical boundary and machine registries remain in configuration.

Core freezes planning evidence, records assumptions and ownership, produces an advisory work-selection audit, creates a plan handoff, records critique dispositions, and decides whether canonical sync is required. After approval it filters work by owner scope, implements the smallest accepted change, updates docs/registry/navigation, runs focused then broader checks, applies the UX gate for user-facing flows, reconciles delivery, and exports continuity. The required documentation work belongs to the same implementation cycle, not a later courtesy task.

Apply an average-user UX gate to user-facing changes: state the primary user outcome, test ordinary comprehension and error recovery, verify accessible labels/keyboard behavior where relevant, and keep expert controls from obscuring the common path. This is a review requirement, not a substitute for product research.

See `docs/CORE_VAULT_MAINTENANCE_PROTOCOL.md` for Core-only vault cleanup.
