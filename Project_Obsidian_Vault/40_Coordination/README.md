This area stores source-only cross-owner requests, implementation-plan
critiques, work-selection audits, update records, and dispositions. It records
convergence history, not canonical project doctrine.

## Start Here

1. Read [[40_Coordination/Instructions/README.md]].
2. Open [[40_Coordination/Generated/Active Records.md]].
3. Inspect only records relevant to the current owner boundary or plan.
4. Verify repository claims against current evidence before acting.

## Record Types

- work-selection audit: frozen source evidence behind one candidate;
- plan critique: advisory attack on assumptions, scope, and verification;
- boundary request: one owner asks another for a public decision or contract;
- response/disposition: the owning decision and remaining action;
- integration handoff: exact branch, commits, target, and named integrator;
- update record: compact navigation over immutable atomic records.

## Critique Contract

A substantive critique records Common Agreement, All Remaining Disagreements,
Critical Weak Points, Convergence Move, and Decision Status. The owning agent
disposes each point as accepted, partially accepted, rejected, deferred, or
requiring user approval.

## Publication

A cross-owner request is delivered only when its record is committed and
reachable from the shared canonical Git history. A note left solely in a local
worktree or unlanded branch cannot establish that the receiving owner missed
or delayed the request. Responses follow the same rule.

## Authority

Coordination does not grant file ownership, activate an owner, change
canonical doctrine, authorize implementation, or certify a result. Review
roles edit only assigned atomic records. Core owns shared indexes and
canonical promotion; each owner controls its own semantic disposition.
