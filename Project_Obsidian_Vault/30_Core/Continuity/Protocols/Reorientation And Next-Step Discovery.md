Use this protocol after context loss, at the start of a substantial Core task,
or when the user asks for the next implementation step.

## Rehydrate

1. Read root policy, Core role, Core bootstrap, and this continuity MOC.
2. Record the first successfully inspected commit and worktree state.
3. Read relevant research records before canonical conclusions.
4. Read current Thesis, Architecture, Spec, Roadmap, Current State, and
   capability registry.
5. Read only relevant A2A records and continuity parts.
6. Inspect current source, tests, configuration, receipts, Git history, and
   the Core integration inbox.

## Select

Separate selection evidence from delivery conditions. Classify capability
states, dependencies, owner boundaries, and canonical/runtime mismatches.
Apply the [[30_Core/Continuity/Protocols/Assumption Audit.md]], then recommend
the smallest unblocked Core-owned gate.

Do not reopen stable selection because of unrelated documentation churn,
generated navigation, or another owner's worktree. Reopen only when a change
touches the selected gate, its material prerequisite, authority, or essential
evidence.

## Report

Report baseline, evidence inspected, current maturity, discrepancies,
challenged assumptions, owner handoffs, and the proposed next step. Planning
does not authorize implementation.
